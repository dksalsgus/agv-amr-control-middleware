# 측정 결과

`node scripts/measure.mjs`를 한 번 돌린 결과입니다(2026-11-19 13:29 KST, docker compose 한 대, 로봇 90대와 PLC 16점). 다시 재려면 같은 명령을 실행합니다.

## 읽는 법

- **수집 지연**은 미들웨어가 받은 시각에서 장비의 발생 시각을 뺀 값이고, **종단 지연**은 화면(측정 스크립트의 WebSocket)이 delta를 받은 시각에서 발생 시각을 뺀 값입니다. 둘의 차이가 미들웨어 처리와 100ms 묶음 전송에 든 시간입니다.
- 폴링 방식(B는 REST, C와 PLC는 Modbus)은 데이터가 생긴 뒤 다음 폴링까지 기다리므로 지연이 0~1초(PLC는 0~0.5초) 더 나옵니다. 폴링 주기와 에뮬레이터 갱신 주기가 둘 다 1초라 위상이 맞물려, 한 번 띄운 동안에는 거의 같은 값이 나오고 띄울 때마다 값이 달라집니다(C는 이번 실행에서 400ms, 앞선 실행에서 800ms). 결함이 아니라 폴링의 성질이라 프로토콜별로 나눠 적습니다.
- 브라우저 화면에서 잰 종단 지연은 관제 웹 조각에서 같은 방식으로 더합니다.
